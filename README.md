# dsh-turn-report

在每一轮回答结束后的**位置**加一张**项目汇报卡**。不调用模型、不消耗 token，全部由宿主从会话日志推导。

## 卡片里有什么

```
📊 本轮项目汇报  第 17 轮
⚙️ deepseek-flash  调用 28 次  in 493k / out 23k · 缓存命中 97%

   项          值
   工具调用     35
   失败         1
   改动文件     6
   结束状态     completed

📄 产出文件  [src/styles/theme.css] [src/Header.tsx]

📝 本轮完成  2 项
✅ 阶段一：调研
✅ 看文档

▰▰▰▰▰▰▱▱▱▱ 2/3  ✅ 2  ⬜ 1   ⏭ 阶段二：实现
📋 当前计划
▸ ✅ 阶段一：调研          2/2
⬜ 阶段二：实现
```

| 块 | 什么时候出现 | 内容 |
|---|---|---|
| 📋 **指标表格** | 每一轮 | 工具调用次数、失败次数（为 0 时省略）、改动文件数、结束状态 |
| ⚙️ **执行摘要** | 本轮有模型响应时 | 模型名 · **模型调用次数** · 输入/输出 token · 缓存命中率 |
| 📄 **改动文件** | 本轮改过文件时 | 相对工作区路径，最多 6 个 |
| 📝 **本轮完成** | 本轮有新打勾的项 | 只列这一轮新完成的 |
| 🎮 **计划 HUD** | 本轮写过清单时 | 进度条 + 分组计划，**每组可单独折叠** |
| 📦 **任务树** | `todoView: tree` / `both` | ASCII 树，作为这一轮的存档 |

### 🎮 计划 HUD：跟在这一轮末尾的状态栏

**两种分组方式，按清单内容自动选择。**

#### ① 阶段模式（推荐）

清单项带 `【阶段】` 前缀时，三个格子显示的是**阶段**，不是任务：

```
2/5  ✅ 2  ⏳ 1  ⬜ 2
⏭ 下一项：搭插件骨架
📋 当前计划
┌ ▶ ✅ 阶段一·调研  2          ← 该阶段全部完成，默认折叠
┌ ▼ ⏳ 阶段二·实现  2
│  ⏳ 搭插件骨架
│  ⬜ 实现投影 fold
┌ ▼ ⬜ 阶段三·发布  1
│  ⬜ 上架市场
```

每个阶段的**状态由它自己的任务决定**：全部完成 → ✅；有进行中 → ⏳；都没开始 → ⬜。

三种括号都认：

```
【阶段一·调研】确认技术路径
〔P1〕搭骨架
[阶段2] 实现投影
```

阶段前缀只在组标题出现一次，组内行会自动剥掉，不占宽度。

#### ② 状态模式（回退）

清单没有阶段标记时，退回按任务状态分三组：

```
┌ ▼ ✅ 已完成  4
┌ ▼ ⏳ 进行中  1
┈ ⬜ 待办  0          ← 空槽：虚线框、半透明、不可点
```

**三格常驻，不因空而隐藏。** 格子时有时无，人第一反应是「它把我的待办弄丢了」。空槽用虚线框 + 半透明表示「此刻这里是 0」，顺序固定。

#### 为什么阶段必须靠前缀

`todo_write` **没有阶段字段**，只有任务状态（completed / in_progress / pending），而且实测载荷 100% 平铺。从数据无法反推「阶段」，所以只能由写清单的人标注。

#### 其他细节
- **进度条自适应宽度**（`flex: 1 1 200px`，最少 140px）
- **0% 时进度条是虚线框**——空的灰条看起来像坏了
- **箭头用 `▼`/`▶`**（实心三角）
- **已完成的组默认折叠**——内容已在上面「📝 本轮完成」里
- 全部完成时进度条变绿并撑满，末尾显示 `✨ 全部完成`

**每张卡片显示的是那一轮结束时的计划快照**，不是当前最新计划。第 1 轮显示 `2/3`，第 2 轮显示 `4/5`——历史卡片不会被最新状态覆盖。

### 每张卡显示什么计划

- **这轮写了清单** → 显示**这一轮**的清单，无标记
- **这轮没写清单** → 显示**仍在生效的最近一份**清单，并打上 `本轮未更新` 标签

两种极端都试过，都不行：

| 做法 | 结果 |
|---|---|
| 没写清单就**不显示** | 74% 的轮次没有 HUD，用户看到「改完后怎么什么都没了」 |
| 没写清单就**显示当前最新** | 十几张卡片复读同一份状态，**没有任何解释**，看起来像卡死 |

现在是中间路线：**显示仍在生效的计划 + 明确标注**。重复有了说明，就不再像 bug。

实测只有 26% 的轮次会写清单（另一个会话 6%），所以「本轮未更新」会是常见形态，这是如实反映。

### 为什么有的轮次没有待办区

数据源是 `todo_write`，**调不调用它由模型自己判断**——它觉得这轮是「需要规划的多步任务」才写，简单改个文件、答个问题就不写。

所以：

- **没待办区 = 这轮确实没在推进一个多步任务**，这个信号本身有用（强行每轮都写会让闲聊变成一堆复选框）
- 派一个明确的多步任务（「给 X 加三个功能」）就会出现

### 修复记录：最后一份清单曾经会丢失

`turn/start` 原本无条件执行 `prevTodos = state.todos`。如果那一轮没写清单，`prevTodos` 就被设成 `null`；**连续两轮没写清单，最后一份真实清单就永久消失**。

实测：某会话在 turn 21 写了 7 项清单，此后 20 多轮没再写，结果 turn 30 之后**待办区完全消失**。已修——`prevTodos` 现在只在有真实清单时更新，跨过任意多轮无清单也不会丢。

回归测试守住了这条：`plan survives 11 plan-less turns`。

### 为什么按状态分组，不按缩进

我一开始按「缩进 = 子项」分组（`todo_write` 没有 parent 字段），结果**箭头一个都不显示**。

查了真实会话日志，原因很直接：

```
indent=""  status=completed  "Host：fold 累加本轮的模型、LLM 调用次数、token 用量"
indent=""  status=completed  "Client：卡片渲染一行执行摘要（模型 · 调用次数 · token）"
indent=""  status=completed  "配置开关 showLlm，stateVersion 提到 5"
...
→ 最后一次里有缩进的项: 0 / 5
```

**真实清单 100% 平铺，没有任何缩进。** 按缩进分组时每项各自成一个分组、都没有子项、都不可折叠，于是箭头全部消失。

改成按状态分组后箭头正常出现。模型若确实写了缩进，缩进仍保留在各组内部的行缩进上，结构不丢。

## 位置说明

状态栏在**轮末卡片里**，跟着每一轮对话，不在输入框附近。

输入框上方有 DSH **原生待办面板**（`conversation.input.dock`，id `todo`），显示当前完整清单。本插件**不重复它**：卡片只报「本轮新增」和「那一轮的计划快照」。

### ⚙️ 执行摘要补的是什么

```
⚙️ deepseek-flash  调用 3 次  in 24k / out 1.8k · 缓存命中 95%
```

**模型调用次数是这一行的核心**——原生用量面板算的是 token 总量，但**从不告诉你模型被问了几次**。一轮花掉 200k token，是「1 次超长上下文」还是「12 次来回」？成本解释完全不同。

鼠标悬停在这一行上能看到精确明细（未缓存输入 / 缓存读 / 缓存写 / 输出 / 合计），数字是各项相加而不是转发 provider 的总数，避免各部分对不上。

> **与原生的分工**：DSH 默认 `performanceUsage: detailed`，轮末会有一个 `⛁ 用量` 按钮，点开是逐项 token 账本（含模型与缓存明细）。本插件**不重复那个弹窗**，只在卡片里给一行常驻摘要，其中只有「调用次数」是原生没有的。嫌重复可以 `showLlm: false` 关掉。

### ⚠️ 为什么不显示「还剩什么」

DSH **原生就有一个待办面板**，在输入框上方，数据源同样是 `todo_write`：

```ts
// dsh-client-ui-conversation/src/client/skeleton/TodoPanel.tsx:107
const todos = useProjection('todos')   // 和本插件读的是同一份数据
```

它显示当前完整清单 + 每项状态 + `N 已完成 · M 待处理` 汇总。**再显示一遍剩余项就是纯重复**——本插件早期版本干过这事，被用户当场发现并砍掉了。

所以卡片只保留原生面板**没有**的那个事实：

| | 原生待办面板 | 本卡片的「本轮完成」 |
|---|---|---|
| 显示 | 当前完整清单（活的） | **本轮新完成了哪些** |
| 时效 | 随时是最新 | 冻结在轮末，可回看 |
| 「还剩多少」 | ✅ 有 | ❌ 刻意不做，去看原生面板 |

```
📝 本轮完成  2 项
✅ 删除过期的 demo-card-simple.png
✅ README 开头改用文字说明
```

「本轮完成」= 现在是 `completed`、且上一轮还不是 `completed` 的项。

`todo_write` 的条目**没有稳定 id**，所以跨轮对比只能按内容匹配。匹配前会剥离列表符号、标题标记、全部空白并忽略大小写，这样把 `- 写测试` 改成 `写测试` 不会被当成新工作。

**但这仍是启发式**：如果模型把某一项的措辞实质改写（`实现按钮` → `完成主题切换控件`），就会被算成本轮新完成。真实场景里模型通常会沿用原措辞，所以影响有限，但你应该知道这个边界。

### 任务树是可选的

树和原生面板数据同源，但原生没有**层级视图**，所以保留它作为选项：

```yaml
todoView: auto   # 默认：只出「本轮完成」，零重复
todoView: tree   # 只出整棵树
todoView: both   # 都出（完成项会重复，仅当你想同时看结构和增量）
```

### 待办区为什么不是每轮都有

待办区的数据源是 `todo_write`，而**调不调用 `todo_write` 由模型自己判断**——它觉得这轮是「需要规划的多步任务」才写，简单问答就不写。

这是有意不改的：强行要求模型每轮都写清单，会让“你好”这种对话也变成一堆复选框，白花 token。**所以没待办区 = 这轮确实没在推进一个多步任务**，这个信号本身是有用的。

想看待办区的话，让我做一件明确的多步任务（比如“给 X 加三个功能”）就够了。

**不调用模型、不消耗 token。** 全部由宿主从会话日志推导，成本是零。

## 一个完整的例子

假设你让 AI 给网站加夜间模式。这一轮它说：

> 我已经把夜间模式的配色表写好了，主题切换按钮做到一半。改动了 theme.css、Header.tsx、Home.tsx，测试跑通了（第一次改 Header 时失败过一次，重试成功）。下一步继续做按钮，然后适配文章详情页和后台管理页。

**它没提** 自己一共调了多少次工具、失败几次。这些它不爱说、你也懒得数。插件替你补上：

```
📊 本轮项目汇报                    第 7 轮
   ✅ 4  ⏳ 1  ⬜ 4

   项            值
   工具调用       13
   失败           1
   改动文件       3
   结束状态       completed

📄 产出文件  [src/styles/theme.css] [src/Header.tsx] [src/pages/Home.tsx]

📝 本轮完成  3 项
✅ 调研 CSS 变量方案
✅ 写好配色表
✅ 首页
```

一眼能看出：**这一轮新做完了 3 件事**，而不是去数聊天记录里翻了多少次工具。
「还剩 4 项、卡在按钮上」看输入框上方那个原生面板——那里随时是最新的，不需要卡片再抄一遍。

<sub>注：上面 📊 行的 ✅⏳⬜ 汇总与任务树需 `todoView: both` 或 `tree` 才显示；默认只出「本轮完成」，避免与原生面板重复。</sub>

本轮没写任务清单时，卡片只出指标和文件，待办区整块不出现（不硬凑）。

## 它为什么不是「往对话里追加一条消息」

DSH 的会话日志是事件溯源的唯一真相源，`Session.append()` 写的事件**不能带 `ignorable` 标记**，而 `appendPluginRecord()` 明确只给 `packages/experimental/` 用、第三方插件不得调用（`dsh-session/README.md` 有明文，且仓库有 `verify-plugin-record-callers` 检查）。所以宿主替模型写一条可见的 assistant 消息，在这个版本上是走不通的。

本插件用的是官方支持的组合：

```
会话日志 ──fold──> sessionProjections (wire view) ──推送──> 浏览器 useProjection
                                                              │
                                              conversation.chat.turnTail 槽位
                                                              │
                                                        轮末汇报卡
```

`turnTail` 槽位就是「本轮已结束、收尾动作行之前」的那块位置（`dsh-client-ui-deliverables` 的改动文件卡、`dsh-client-ui-plan` 的计划卡都挂在这里）。

## 安装

```powershell
dsh plugin --profile desktop add file:"D:\path\to\dsh-turn-report"
```

装完**重启 DSH**，刷新页面。已在 `desktop` profile 的 DSH 0.2.2-rc.5 上安装成功（`application: applied`）。

## 它从哪里拿数据

| 数据 | 来源 |
|---|---|
| 待办清单 | `todo_write` 快照（`todo/write` 事件，整表覆盖） |
| 工具调用 / 失败 | 本轮 `tool/call`、`tool/result.message.isError` |
| 改动文件 | `write`/`edit`/`multi_edit`/`insert`/`str_replace_editor` 等工具的参数 |
| 轮次边界 | `turn/start`、`turn/end`（含结束原因） |

改动文件显示为**相对工作区**的路径（例如 `src/styles/theme.css`），工作区外的文件保留绝对路径；完整路径始终在该标签的 `title` 提示里。

### 任务清单是本轮的，不是累积的

`todo_write` 是**整表覆盖**，且宿主自己的 `todos` 投影会在 `turn/start` 清空。本插件跟随同一语义：**本轮没写清单就没有清单**，不会拿上一轮的旧清单冒充当前进度。

### 任务树的层级从哪来

`todo_write` 的条目**没有 parent 字段**（只有 `content` 和 `status`），所以树只认你在内容里写的前导空格（2 空格 = 一层，4 空格 = 两层），并自动剥掉 `-` / `1.` 这类列表符号。这是当前数据模型里唯一可用的层级来源，它**不是**真正的父子关系。

## 配置

在 profile 的 `cordis.patch.yml` 里覆盖同一行（整份 `config` 替换，不是深合并）：

```yaml
- id: turn-report
  config:
    maxRows: 6              # 表格/树/分组最多列几条（硬上限 20）
    showWithoutTasks: true  # 本轮没有待办清单时，还出不出卡
    showTree: true          # 允许画 ASCII 项目树
    showFiles: true         # 列不列改动文件
    showFinished: true      # 允许出「本轮完成」清单
    showLlm: true           # 允许出「模型 · 调用次数 · token」摘要行
    showStatusBar: true     # 允许出计划 HUD（进度条 + 可折叠分组）
    todoView: auto          # 任务树出不出，见下
```

`todoView` 三个值：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 只出「本轮完成」+ 计划 HUD，不出 ASCII 树 |
| `tree` | 不出「本轮完成」，只出整棵 ASCII 树 |
| `both` | 全部出（完成项会重复） |

> 兼容旧配置：`showPending` 会被当作 `showFinished` 的别名；`todoView: pending` 会被当作 `auto`。改语义是为了消除与原生待办面板的重复，见开头说明。

## 已知边界

- 卡片挂在 `conversation.chat.turnTail` 槽位，只在一轮**已经结束**时出现。
- **待办区不是每轮都有**——只有模型这一轮调用过 `todo_write` 才画。这是有意的（见开头），想要就派一个明确的多步任务。
- **本插件不显示「还剩什么」**：那是原生输入框上方待办面板的职责，重复显示没有价值。
- 「本轮完成」按归一化后的内容匹配上一轮清单来算（剥符号/空白/大小写）。模型实质改写措辞会把该项当成新工作，这是无法避免的边界——`todo_write` 没有稳定 id。
- 只保留最近 15 轮的报告，更早的轮次不再出卡（滚出窗口即消失，不是永久账本）。
- 任务树是**单轮快照**，不是跨轮累积的项目台账——`todo_write` 每轮被模型整表重写，插件拿不到稳定身份做长期追踪。
- 不写任何文件。状态全在会话投影里，随会话日志一起持久化。
- **「本轮完成」和分组内每项的行数上限是 20**（`HARD_MAX_ROWS`），不受 `maxRows` 影响。之前默认 `maxRows: 6` 会把第 7 项起标成「… 还有 N 条未展开」，看起来像内容丢了。

## 实测记录（本机 desktop profile）

本会话 8 轮对话里，只有 1 轮写了任务清单：

| 轮次 | 工具调用 | 失败 | 改动文件 | 待办区 |
|---|---|---|---|---|
| turn 1 | 42 | 0 | 1 | 无（没写清单） |
| **turn 2** | 139 | 3 | 6 | **有：8 项全完成** |
| turn 3 | 100 | 2 | 5 | 无 |
| turn 4 | 10 | 0 | 0 | 无 |
| turn 5 | 12 | 0 | 1 | 无 |
| turn 6–8 | 5 / 25 / 34 | 0 | 0 / 5 / 6 | 无 |

**8 轮里只有 1 轮有待办区。** 只有做插件开发那轮（明确的多步任务）才写了清单，其余简单轮次只有指标表——这就是“常见形态”和“罕见形态”的真实比例，不是 bug。
